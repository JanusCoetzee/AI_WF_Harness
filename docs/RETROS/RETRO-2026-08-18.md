## Harness tooling bug found

`scripts/gate-check.sh`'s `need_file()` flags a `CHANGE.md` as an "unfilled
template" if the literal string `CHG-###` appears anywhere in it —
including in prose that legitimately *talks about* the placeholder pattern
(e.g. "§5 traceability (change ID referenced in commit)" had to be reworded
specifically to dodge this false positive; the original wording read
"`CHG-###` in commit" and tripped the check even though every real field in
the document was filled in). The regex should distinguish "template
placeholder left in a value position" from "the literal string mentioned in
prose" — e.g. only flag it inside table cells, or require it isolated on its
own or at line-start, not merely present anywhere in the file. **This is
generic to `gate-check.sh` and will hit every future `CHG-###`/`G#` doc that
ever needs to reference the ID pattern itself in explanatory text — worth
fixing upstream in `AI_WF_Harness`, not just patching locally.**

## Ceremony audit

`templates/CHANGE.md`'s FinServ-inherited fields — **Linked records**,
**Timing constraints**, and the conditional **Regulated / reported outputs**
section — produced zero value on CHG-001: they were answered "none" /
deleted outright, exactly as any T3 personal-repo change will answer them,
every time, forever. The template's own instruction ("'none' only after
checking") is right for T1 (money movement, real audit trail) and pure
overhead for T3 (a static study-resource site). Propose: a **T3-tier
variant** of `templates/CHANGE.md` that collapses those three fields to one
line — `Regulatory/audit surface: none (T3 — see harness.config.yaml)` — by
default, with a note that upgrading the tier restores the full fields. This
keeps the FinServ rigor for repos that need it without making every trivial
T3 change fill in bank-audit boilerplate that is never true for it.
